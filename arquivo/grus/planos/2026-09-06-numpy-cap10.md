## 2. O módulo `scratch_np/naive_bayes.py`

Dono: capítulo 10. **Ninguém mais importa deste módulo** (`scratch_np/machine_learning.py` já diz na docstring que o cap. 10 importa dele, e não o contrário). Nada de `random`, nada de `rng`: o modelo não sorteia — quem sorteia é o `split_data` de quem chama.

Código completo, pronto para salvar. Os chunks das seções 10.3 e 10.4 são **idênticos** a estes blocos (o módulo é o chunk salvo em arquivo).

```python
"""Naive Bayes com numpy — o que o capítulo 10 ensina.

A seção 10.3 escreve `tokenize`, `Message`, `NaiveBayesClassifier` e `predict`
inline; as seções 10.4 e 10.5 importam daqui. O código é o mesmo dos chunks — o
módulo é o chunk salvo em arquivo. Nenhum outro capítulo importa deste módulo.

O modelo não sorteia nada: a divisão treino/teste é de quem chama, com o `rng`
de `scratch_np.machine_learning.split_data`.
"""
from typing import Iterable, NamedTuple, Set, Tuple
from collections import Counter
import re

import numpy as np


def tokenize(text: str) -> Set[str]:
    text = text.lower()                          # Converte para minúsculas,
    all_words = re.findall("[a-z0-9']+", text)   # extrai as "palavras", e
    return set(all_words)                        # remove as duplicadas.


assert tokenize("Data Science is science") == {"data", "science", "is"}


class Message(NamedTuple):
    text: str
    is_spam: bool


class NaiveBayesClassifier:
    def __init__(self, k: float = 0.5) -> None:
        self.k = k  # fator de suavização

        self.tokens: np.ndarray = np.array([], dtype=str)
        self.token_spam_counts: np.ndarray = np.array([], dtype=int)
        self.token_ham_counts: np.ndarray = np.array([], dtype=int)
        self.spam_messages = self.ham_messages = 0

    def train(self, messages: Iterable[Message]) -> None:
        spam_counts: Counter = Counter()
        ham_counts: Counter = Counter()

        for message in messages:
            # Incrementa as contagens de mensagens
            if message.is_spam:
                self.spam_messages += 1
            else:
                self.ham_messages += 1

            # Incrementa as contagens de palavras
            for token in tokenize(message.text):
                if message.is_spam:
                    spam_counts[token] += 1
                else:
                    ham_counts[token] += 1

        # A varredura acabou e o vocabulário está fechado: ele vira um array
        # ORDENADO, e as duas contagens viram arrays alinhados a ele — a
        # posição i é sempre o token self.tokens[i], em todos os três.
        self.tokens = np.array(sorted(spam_counts.keys() | ham_counts.keys()))
        self.token_spam_counts = np.array([spam_counts[t] for t in self.tokens],
                                          dtype=int)
        self.token_ham_counts = np.array([ham_counts[t] for t in self.tokens],
                                         dtype=int)

    def _probabilities(self) -> Tuple[np.ndarray, np.ndarray]:
        """P(token | spam) e P(token | ham) para todo o vocabulário, de uma vez."""
        p_token_spam = (self.token_spam_counts + self.k) / (self.spam_messages + 2 * self.k)
        p_token_ham = (self.token_ham_counts + self.k) / (self.ham_messages + 2 * self.k)

        return p_token_spam, p_token_ham


def predict(self, text: str) -> float:
    p_spam, p_ham = self._probabilities()

    # A máscara: True nas posições cujo token aparece na mensagem.
    presentes = np.isin(self.tokens, list(tokenize(text)))

    # Presente: soma log(p). Ausente: soma log(1 - p). Numa redução só.
    log_prob_if_spam = np.sum(np.where(presentes, np.log(p_spam), np.log(1 - p_spam)))
    log_prob_if_ham = np.sum(np.where(presentes, np.log(p_ham), np.log(1 - p_ham)))

    prob_if_spam = np.exp(log_prob_if_spam)
    prob_if_ham = np.exp(log_prob_if_ham)
    return float(prob_if_spam / (prob_if_spam + prob_if_ham))


NaiveBayesClassifier.predict = predict


# O exemplo de brinquedo da seção 10.4 — o render é o teste.
_messages = [Message("spam rules", is_spam=True),
             Message("ham rules", is_spam=False),
             Message("hello ham", is_spam=False)]

_model = NaiveBayesClassifier(k=0.5)
_model.train(_messages)

assert np.array_equal(_model.tokens, np.array(["ham", "hello", "rules", "spam"]))
assert _model.spam_messages == 1
assert _model.ham_messages == 2
assert np.array_equal(_model.token_spam_counts, np.array([0, 0, 1, 1]))
assert np.array_equal(_model.token_ham_counts, np.array([2, 1, 1, 0]))

# As probabilidades de "hello spam", na ordem do vocabulário.
_probs_if_spam = np.array([
    1 - (0 + 0.5) / (1 + 2 * 0.5),  # "ham"   (ausente)
    (0 + 0.5) / (1 + 2 * 0.5),      # "hello" (presente)
    1 - (1 + 0.5) / (1 + 2 * 0.5),  # "rules" (ausente)
    (1 + 0.5) / (1 + 2 * 0.5),      # "spam"  (presente)
])
_probs_if_ham = np.array([
    1 - (2 + 0.5) / (2 + 2 * 0.5),  # "ham"   (ausente)
    (1 + 0.5) / (2 + 2 * 0.5),      # "hello" (presente)
    1 - (1 + 0.5) / (2 + 2 * 0.5),  # "rules" (ausente)
    (0 + 0.5) / (2 + 2 * 0.5),      # "spam"  (presente)
])

_p_if_spam = np.exp(np.sum(np.log(_probs_if_spam)))
_p_if_ham = np.exp(np.sum(np.log(_probs_if_ham)))

# Deve dar aproximadamente 0,835 — e comparado com tolerância, não com ==.
assert np.isclose(_model.predict("hello spam"),
                  _p_if_spam / (_p_if_spam + _p_if_ham))
```

Três decisões deste módulo, para o revisor não ter que adivinhar:

1. **`_probabilities()` perdeu o parâmetro `token`.** Ela devolve os dois arrays do vocabulário inteiro, alinhados a `self.tokens` — é a forma vetorizada da mesma fórmula, e é o que `predict` e a seção 10.5 (as palavras mais spammy) consomem. O nome continua o do Grus, como a spec exige; a aridade não podia continuar, porque uma versão por token seria um laço disfarçado.
2. **As duas `Counter` são locais ao `train`.** Enquanto o vocabulário está sendo descoberto não se sabe o tamanho do array, e é aí que um dicionário é a estrutura certa; assim que a varredura acaba, o tamanho é conhecido e a contagem vira array. Consequência honesta: chamar `train` duas vezes **não** acumula (o modelo do Grus acumulava). Ninguém chama duas vezes; a docstring do módulo e o `.exemplo` da 10.3 dizem que `train` consolida.
3. **`spam_counts[t]` num `Counter` devolve 0 sem inserir a chave** — é por isso que aqui é `Counter` e não `defaultdict(int)`, que inseriria uma chave a cada consulta.

#| label: naive-bayes-classifier
from typing import Iterable, Tuple
from collections import Counter
import numpy as np

class NaiveBayesClassifier:
    def __init__(self, k: float = 0.5) -> None:
        self.k = k  # fator de suavização

        self.tokens: np.ndarray = np.array([], dtype=str)
        self.token_spam_counts: np.ndarray = np.array([], dtype=int)
        self.token_ham_counts: np.ndarray = np.array([], dtype=int)
        self.spam_messages = self.ham_messages = 0

    def train(self, messages: Iterable[Message]) -> None:
        spam_counts: Counter = Counter()
        ham_counts: Counter = Counter()

        for message in messages:
            # Incrementa as contagens de mensagens
            if message.is_spam:
                self.spam_messages += 1
            else:
                self.ham_messages += 1

            # Incrementa as contagens de palavras
            for token in tokenize(message.text):
                if message.is_spam:
                    spam_counts[token] += 1
                else:
                    ham_counts[token] += 1

        # A varredura acabou e o vocabulário está fechado: ele vira um array
        # ORDENADO, e as duas contagens viram arrays alinhados a ele — a
        # posição i é sempre o token self.tokens[i], em todos os três.
        self.tokens = np.array(sorted(spam_counts.keys() | ham_counts.keys()))
        self.token_spam_counts = np.array([spam_counts[t] for t in self.tokens],
                                          dtype=int)
        self.token_ham_counts = np.array([ham_counts[t] for t in self.tokens],
                                         dtype=int)

    def _probabilities(self) -> Tuple[np.ndarray, np.ndarray]:
        """P(token | spam) e P(token | ham) para todo o vocabulário, de uma vez."""
        p_token_spam = (self.token_spam_counts + self.k) / (self.spam_messages + 2 * self.k)
        p_token_ham = (self.token_ham_counts + self.k) / (self.ham_messages + 2 * self.k)

        return p_token_spam, p_token_ham

def predict(self, text: str) -> float:

    # A máscara: True nas posições cujo token aparece na mensagem.

## Um `assert` que compara `float` por igualdade exata

O @grus2019 escreve a linha acima assim: `model.predict(text) == p_if_spam / (p_if_spam + p_if_ham)`. Não é uma comparação com tolerância — é igualdade **exata** de ponto flutuante entre dois cálculos que chegam ao mesmo valor por caminhos diferentes. E soma de ponto flutuante não é associativa: a ordem em que os termos são somados pode mudar o último bit do resultado, o que basta para `==` responder `False`.

No código do Grus a ordem era o problema declarado: o `predict` dele soma percorrendo `self.tokens`, que lá é um `Set[str]`, e a ordem de iteração de um `set` depende do hash de cada string — que o Python randomiza por processo, a menos que a variável de ambiente `PYTHONHASHSEED` esteja fixada. O mesmo `assert`, rodado de novo, podia somar em outra ordem e estourar.

Aqui o vocabulário é um array ordenado, e essa causa some: a ordem da soma é sempre a mesma. Isso **não** conserta o `assert` — só troca o motivo pelo qual ele é frágil. `np.sum` não soma da esquerda para a direita: ele usa soma pareada, que quebra o array em blocos e soma os blocos entre si, justamente para acumular menos erro. O agrupamento depende do **tamanho** do array, então a mesma soma, sobre um vocabulário maior, é feita em outra ordem — e o último bit muda de novo. Escrever `==` continua sendo apostar num detalhe de implementação que ninguém prometeu.

## 4. Riscos e decisões

1. **`_probabilities()` mudou de aridade.** Deixou de receber um token e passou a devolver o vocabulário inteiro em dois arrays. É o único desvio de assinatura em relação ao @grus2019 neste capítulo, e ele é o que torna `predict` e as "palavras spammy" vetorizáveis. O nome fica; a spec exige nomes do Grus, não aridades do Grus. Nenhum outro capítulo importa este módulo, então o desvio não se propaga.

2. **`predict` continua fora da classe.** O callout `## Por que predict nasceu fora da classe` sobrevive inteiro, e continua sendo a única explicação do livro de que um método é uma função guardada num atributo da classe. Alternativa considerada e recusada: com seis linhas, `predict` caberia dentro do `class` — mas aí o capítulo perderia o callout, a máscara perderia a introdução própria, e a mudança seria churn sem ganho.

3. **Igualdade exata de `float`: a causa mudou, a lição não.** Medido: as previsões da versão em arrays e da versão em dicionários do Grus batem em todas as 825 decisões, com diferença máxima de 9,1 × 10⁻¹³, mas **só 31 das 825 são iguais bit a bit**.
