## A boa notícia que decide metade do capítulo

O ajuste deste capítulo é gradiente descendente **estocástico com ordem de lote
fixa**, e a seção 12.2 já demonstrava (chunk `ciclo-limite`) que ele converge
para uma **órbita estável que não depende do chute inicial**: quatro ajustes com
sementes e números de passos diferentes davam o mesmo `beta` bit a bit. Isso
continua valendo em arrays, e a consequência é grande:

**trocar `random.random()` por `rng.random(d)` no chute inicial não muda o
`beta` final.** Medido: `default_rng(0)`, 5.000 passos, lotes de 25 →
`[30.514821035880658, 0.97482608691215, -1.8506922128881964, 0.9140582640635172]`,
exatamente os 30,51 / 0,975 / −1,851 / 0,914 que o capítulo já publica, e
R² = 0,679985, o mesmo 0,679985 que a seção 12.5 cita.

Portanto: **quase todos os números do capítulo sobrevivem à reescrita.** Os que
mudam são só os que dependem de um **sorteio de dados**, não de um chute
inicial: os coeficientes por semente da 12.2 (`colinear`), o bootstrap de
medianas da 12.6, os erros padrão da 12.7, e o R² das colunas de ruído da 12.5.
Cada um está medido abaixo.

O que muda de verdade na prosa é o **tempo**: o ajuste caiu de "quase um
segundo" para 0,17 s, e o bootstrap de 100 ajustes de "90 segundos" para
**19 s** [medido]. Toda frase sobre custo precisa ser reescrita, e a barra de
progresso do `tqdm` sai (§4).

```python
"""Regressão múltipla com numpy — o que o capítulo 12 ensina.

As seções 12.3, 12.5, 12.6, 12.7 e 12.8 escrevem estas funções inline num
chunk; as seções seguintes — e o capítulo 13 — importam daqui O MESMO código.
O módulo é o chunk salvo em arquivo.

Os dados (`inputs`: 203 linhas de [1, amigos, horas de trabalho, doutorado])
moram em `scratch/multiple_regression.py` e entram aqui como array. É a única
razão para um arquivo de `scratch_np/` importar `scratch.`: dado, nunca função.

Importar o módulo do Grus tem dois efeitos colaterais, e nenhum se corrige
editando o pacote vendorizado. Ele desenha figuras (via `scratch.statistics` e
`scratch.probability`) — daí o `plt.close("all")`. E ele roda, no nível do
módulo, um bootstrap de medianas com o `random` da stdlib SEM semente: os dois
`assert` daquele bootstrap são robustos, mas o sorteio não é reprodutível. O
`random.seed(0)` abaixo o torna reprodutível. É a única linha de `random` da
stdlib deste pacote, e existe só para o import ser determinístico.

Convenções: `X` tem forma (n, d), `y` tem forma (n,), `beta` tem forma (d,).
As funções que devolvem escalar devolvem `float`, com uma exceção deliberada:
`predict`, `error` e `squared_error` aceitam um ponto (d,) OU uma matriz
(n, d) e devolvem, respectivamente, um escalar ou um array de n valores. É
essa polimorfia que faz `multiple_r_squared` caber numa linha.
"""
import random
from typing import Callable, Union

import numpy as np
from matplotlib import pyplot as plt

# ver o docstring: sem isto, o import sorteia
random.seed(0)
from scratch import multiple_regression as _grus

plt.close("all")

from scratch_np.gradient_descent import gradient_step
from scratch_np.probability import normal_cdf
from scratch_np.simple_linear_regression import total_sum_of_squares

# 203 usuários: [1, número de amigos, horas de trabalho por dia, tem doutorado]
inputs: np.ndarray = np.array(_grus.inputs, dtype=float)

assert inputs.shape == (203, 4)
assert inputs[0].tolist() == [1.0, 49.0, 4.0, 0.0]


def predict(x: np.ndarray, beta: np.ndarray) -> Union[float, np.ndarray]:
    """assume que o primeiro elemento de x é 1

    x com forma (d,) devolve a previsão daquele ponto; X com forma (n, d)
    devolve as n previsões, uma por linha.
    """
    return x @ beta


def error(x: np.ndarray, y, beta: np.ndarray) -> Union[float, np.ndarray]:
    return predict(x, beta) - y


def squared_error(x: np.ndarray, y, beta: np.ndarray) -> Union[float, np.ndarray]:
    return error(x, y, beta) ** 2


_x = np.array([1.0, 2.0, 3.0])
_y = 30.0
_beta = np.array([4.0, 4.0, 4.0])   # previsão = 4 + 8 + 12 = 24

assert error(_x, _y, _beta) == -6
assert squared_error(_x, _y, _beta) == 36


def sqerror_gradient(x: np.ndarray, y: float, beta: np.ndarray) -> np.ndarray:
    """o gradiente do erro quadrático de UM ponto x, com forma (d,)"""
    return 2 * error(x, y, beta) * x


assert np.array_equal(sqerror_gradient(_x, _y, _beta), [-12, -24, -36])


def least_squares_fit(xs: np.ndarray,
                      ys: np.ndarray,
                      rng: np.random.Generator,
                      learning_rate: float = 0.001,
                      num_steps: int = 1000,
                      batch_size: int = 1) -> np.ndarray:
    """
    Encontra o beta que minimiza a soma dos erros ao quadrado,
    supondo o modelo y = x @ beta.
    """
    # Começa com um chute aleatório
    guess = rng.random(xs.shape[1])

    for _ in range(num_steps):
        for start in range(0, len(xs), batch_size):
            batch_xs = xs[start:start + batch_size]
            batch_ys = ys[start:start + batch_size]

            # a média, sobre o lote, de 2 * erro_i * x_i
            erros = batch_xs @ guess - batch_ys
            gradient = 2 * batch_xs.T @ erros / len(batch_xs)

            guess = gradient_step(guess, gradient, -learning_rate)

    return guess


def multiple_r_squared(xs: np.ndarray, ys: np.ndarray, beta: np.ndarray) -> float:
    sum_of_squared_errors = float(np.sum(error(xs, ys, beta) ** 2))
    return 1.0 - sum_of_squared_errors / total_sum_of_squares(ys)


def bootstrap_sample(data: np.ndarray, rng: np.random.Generator) -> np.ndarray:
    """sorteia len(data) linhas de data, com reposição"""
    return data[rng.integers(0, len(data), len(data))]


def bootstrap_statistic(data: np.ndarray,
                        stats_fn: Callable[[np.ndarray], Union[float, np.ndarray]],
                        num_samples: int,
                        rng: np.random.Generator) -> np.ndarray:
    """avalia stats_fn sobre num_samples amostras bootstrap de data

    Devolve um array com uma linha por reamostra: forma (num_samples,) se
    stats_fn devolve um número, (num_samples, d) se devolve um vetor.
    """
    return np.array([stats_fn(bootstrap_sample(data, rng))
                     for _ in range(num_samples)])


# 101 pontos todos perto de 100; e 101 pontos, 50 perto de 0 e 50 perto de 200
_rng = np.random.default_rng(0)
_close_to_100 = 99.5 + _rng.random(101)
_far_from_100 = np.concatenate([99.5 + _rng.random(1),
                                _rng.random(50),
                                200 + _rng.random(50)])

_rng = np.random.default_rng(0)
assert np.std(bootstrap_statistic(_close_to_100, np.median, 100, _rng), ddof=1) < 1
assert np.std(bootstrap_statistic(_far_from_100, np.median, 100, _rng), ddof=1) > 90


def p_value(beta_hat_j: float, sigma_hat_j: float) -> float:
    if beta_hat_j > 0:
        # se o coeficiente é positivo, precisamos calcular o dobro da
        # probabilidade de ver um valor ainda *maior*
        return float(2 * (1 - normal_cdf(beta_hat_j / sigma_hat_j)))
    else:
        # caso contrário, o dobro da probabilidade de ver um valor *menor*
        return float(2 * normal_cdf(beta_hat_j / sigma_hat_j))


assert p_value(30.58, 1.27)   < 0.001  # termo constante
assert p_value(0.972, 0.103)  < 0.001  # amigos
assert p_value(-1.865, 0.155) < 0.001  # horas de trabalho
assert p_value(0.923, 1.249)  > 0.4    # doutorado


# alpha é um *hiperparâmetro* que controla a força da penalidade.
# Às vezes ele é chamado de "lambda", mas isso já significa algo em Python.
def ridge_penalty(beta: np.ndarray, alpha: float) -> float:
    return float(alpha * (beta[1:] @ beta[1:]))


def squared_error_ridge(x: np.ndarray, y: float,
                        beta: np.ndarray, alpha: float) -> float:
    """erro estimado mais a penalidade ridge sobre beta"""
    return error(x, y, beta) ** 2 + ridge_penalty(beta, alpha)


def ridge_penalty_gradient(beta: np.ndarray, alpha: float) -> np.ndarray:
    """gradiente apenas da penalidade ridge"""
    return np.concatenate([[0.0], 2 * alpha * beta[1:]])


def sqerror_ridge_gradient(x: np.ndarray, y: float,
                           beta: np.ndarray, alpha: float) -> np.ndarray:
    """
    o gradiente correspondente ao i-ésimo termo de erro quadrático,
    incluindo a penalidade ridge
    """
    return sqerror_gradient(x, y, beta) + ridge_penalty_gradient(beta, alpha)


def least_squares_fit_ridge(xs: np.ndarray,
                            ys: np.ndarray,
                            alpha: float,
                            rng: np.random.Generator,
                            learning_rate: float = 0.001,
                            num_steps: int = 1000,
                            batch_size: int = 1) -> np.ndarray:
    guess = rng.random(xs.shape[1])

    for _ in range(num_steps):
        for start in range(0, len(xs), batch_size):
            batch_xs = xs[start:start + batch_size]
            batch_ys = ys[start:start + batch_size]

            # a penalidade não depende do ponto: a média dela sobre o lote é
            # ela mesma, e por isso ela entra somada uma vez só
            erros = batch_xs @ guess - batch_ys
            gradient = (2 * batch_xs.T @ erros / len(batch_xs)
                        + ridge_penalty_gradient(guess, alpha))

            guess = gradient_step(guess, gradient, -learning_rate)

    return guess


def lasso_penalty(beta: np.ndarray, alpha: float) -> float:
    return float(alpha * np.abs(beta[1:]).sum())


# estes dois não são do Grus: são a conferência do módulo, com números exatos
assert ridge_penalty(np.array([0.0, 3.0, 4.0]), 1.0) == 25
assert lasso_penalty(np.array([0.0, 3.0, -4.0]), 1.0) == 7
```

Grus). Não há ajuste no nível do módulo — nada aqui custa mais que
milissegundos, ao contrário de `simple_linear_regression`, que ajusta no import
porque a 11.2 precisa do resultado.

### Decisões de projeto do módulo

1. **Lotes por fatia, não por `minibatches`.** `least_squares_fit` percorre
   `for start in range(0, len(xs), batch_size)` com fatias, como o Grus. Não usa
   `minibatches(n, batch_size, rng, shuffle=False)` do andaime por três razões:
   a correspondência com o código do livro-texto fica literal; a **ordem fixa
   dos lotes** — de que depende todo o argumento do ciclo-limite da 12.2 — fica
   visível no laço em vez de escondida num parâmetro; e a fatia é uma *view*,
   enquanto o índice avulso copia (medido: 0,165 s contra 0,232 s por ajuste, e
   o bootstrap paga isso 100 vezes). Com 203 pontos e lotes de 25 são **9
   lotes** por passo (oito de 25 e um de 3), como no Grus.
2. **Sem `tqdm`.** Ver §4.
3. **`bootstrap_statistic` devolve `np.ndarray`**, não lista. É o que permite
   `np.std(bootstrap_betas, axis=0, ddof=1)` na 12.7 sem um `np.array(...)` no
   caminho, e `axis=0` é exatamente o vocabulário do bloco 7.1.
4. **`predict`/`error`/`squared_error` não convertem para `float`.** São as
   únicas funções polimórficas do módulo (ponto ou matriz); um `float()` ali
   quebraria `error(inputs, y, beta)`, que é como a 12.5 calcula o R².
5. **`random.seed(0)` no topo** — registrado no docstring e em §4.

```{python}
                      batch_size: int = 1) -> np.ndarray:
    """
    Encontra o beta que minimiza a soma dos erros ao quadrado,
    supondo o modelo y = x @ beta.
    """
    # Começa com um chute aleatório
    guess = rng.random(xs.shape[1])

    for _ in range(num_steps):
        for start in range(0, len(xs), batch_size):
            batch_xs = xs[start:start + batch_size]
            batch_ys = ys[start:start + batch_size]

            # a média, sobre o lote, de 2 * erro_i * x_i
            erros = batch_xs @ guess - batch_ys
            gradient = 2 * batch_xs.T @ erros / len(batch_xs)

            guess = gradient_step(guess, gradient, -learning_rate)

    return guess
```

Prosa — **substituir o parágrafo l. 92 inteiro** por três parágrafos, porque
aqui aparece pela primeira vez no livro o `.T @` como "soma sobre os pontos", e
essa passagem é a única coisa realmente nova do capítulo:

> Dois laços, e eles não são do mesmo tipo. O de fora percorre os **passos** do
> gradiente descendente e o de dentro percorre os **lotes**: os dois *são* o
> algoritmo da [seção 5.6](../cap05/06-minibatch-e-estocastico.qmd), e por isso
> continuam escritos como laço. O que sumiu foi o terceiro, o que percorria os
> pontos **dentro** de cada lote calculando um gradiente por ponto para depois
> tirar a média. Esse virou duas linhas de array, e vale acompanhar a passagem.
>
> O gradiente do lote é a média, sobre os pontos do lote, de $2\,e_i\,x_i$, onde
> $e_i = x_i \cdot \beta - y_i$ é o erro daquele ponto. A primeira linha calcula
> **todos** os $e_i$ de uma vez: `batch_xs @ guess` são as previsões do lote
> (uma por linha, como a [seção 12.1](01-o-modelo.qmd) mostrou) e a subtração de
> `batch_ys` é elemento a elemento. Sobra somar os $x_i$ pesados pelos $e_i$ — e
> essa soma é exatamente o que `batch_xs.T @ erros` faz. Transpor coloca cada
> **ponto** numa coluna; multiplicar por `erros` pesa a coluna $i$ por $e_i$ e
> soma todas. As formas contam a história: `batch_xs.T` é `(d, m)`, `erros` é
> `(m,)`, e o produto é `(d,)` — um número por coeficiente, que é precisamente o
> que um gradiente tem que ser. Dividir por `len(batch_xs)` troca a soma pela
> média, que é o que o Grus faz com `vector_mean`.
>
> Guarde o padrão `X.T @ (algo por ponto)`: ele é "somar sobre os pontos" em uma
> operação, e vai reaparecer em todo modelo linear deste livro. Fora ele, não há
> nada de novo aqui, e esse é o ponto. `gradient_step` é a mesma função do
> [Capítulo 5](../cap05/03-usando-o-gradiente.qmd), agora em arrays. A ordem dos
> lotes é fixa — `range(0, len(xs), batch_size)` fatia sempre igual, como no
> [Grus](https://github.com/joelgrus/data-science-from-scratch) —, e a
> [seção 12.2](02-hipoteses-do-minimos-quadrados.qmd) já mostrou a consequência
> disso. Passar de uma variável explicativa para três não exigiu **nenhuma**
> mudança no otimizador: só que o gradiente devolvesse um vetor mais comprido.

```{python}
def bootstrap_sample(data: np.ndarray, rng: np.random.Generator) -> np.ndarray:
```

```{python}
#| label: estimate-sample-beta
import numpy as np

from scratch_np.multiple_regression import (
    inputs, least_squares_fit, bootstrap_statistic, p_value,
)
from scratch_np.statistics import daily_minutes_good

learning_rate = 0.001

# cada linha é um par (x_i, y_i): as quatro colunas de inputs mais os minutos
pares = np.column_stack([inputs, daily_minutes_good])

def estimate_sample_beta(amostra: np.ndarray) -> np.ndarray:
    x_sample = amostra[:, :-1]     # todas as colunas menos a última
    y_sample = amostra[:, -1]      # a última
```

```{python}
#| label: valor-p
from scratch_np.probability import normal_cdf

def p_value(beta_hat_j: float, sigma_hat_j: float) -> float:
    if beta_hat_j > 0:
        # se o coeficiente é positivo, precisamos calcular o dobro da
        # probabilidade de ver um valor ainda *maior*
        return float(2 * (1 - normal_cdf(beta_hat_j / sigma_hat_j)))
    else:
        # caso contrário, o dobro da probabilidade de ver um valor *menor*
        return float(2 * normal_cdf(beta_hat_j / sigma_hat_j))

# os coeficientes abaixo são a solução exata do sistema de mínimos quadrados;
# os nossos, na tabela acima, vêm do gradiente descendente e diferem na
# segunda ou terceira casa. Os erros padrão são os do Grus, também do bootstrap.
```

```{python}
# alpha é um *hiperparâmetro* que controla a força da penalidade.
# Às vezes ele é chamado de "lambda", mas isso já significa algo em Python.
def ridge_penalty(beta: np.ndarray, alpha: float) -> float:
    return float(alpha * (beta[1:] @ beta[1:]))

def squared_error_ridge(x: np.ndarray, y: float,
```

```{python}
#| label: ridge-gradient
def ridge_penalty_gradient(beta: np.ndarray, alpha: float) -> np.ndarray:
    """gradiente apenas da penalidade ridge"""
    return np.concatenate([[0.0], 2 * alpha * beta[1:]])

                           beta: np.ndarray, alpha: float) -> np.ndarray:

    o gradiente correspondente ao i-ésimo termo de erro quadrático,
    incluindo a penalidade ridge

    return sqerror_gradient(x, y, beta) + ridge_penalty_gradient(beta, alpha)
```

## 4. Riscos e decisões

1. **O ciclo-limite é o que segura o capítulo.** Quase todos os números
   sobrevivem porque o SGD com ordem de lote fixa converge para uma órbita que
   não depende do chute inicial. Se o implementador mudar a **ordem dos lotes**
   (embaralhando, ou usando `minibatches` com `shuffle=True`), *todos* os números
   do capítulo mudam e o callout do ciclo-limite da 12.2 deixa de ser verdade. A
   ordem fixa não é detalhe de implementação: é conteúdo.
2. **`tqdm` sai.** O ajuste leva 0,17 s [medido] — 45 mil gradientes que o numpy
   resolve em overhead de chamada. Uma barra de progresso para 0,17 s é ruído, e
   o capítulo 11 já estabeleceu o precedente (tirou a dele, que rodava em
   0,05 s). Consequências: `#| warning: false` sai dos chunks de ajuste (existia
   para engolir a barra); a frase *"sem barra de progresso"* do callout
   `scikit-learn` da 12.3 sai; o módulo não importa `tqdm`.
   **Limiar para reverter:** se, na máquina do implementador, o chunk
   `bootstrap-betas` passar de ~30 s, ponha `tqdm.trange` **sobre as 100
   reamostras** (não dentro do ajuste) e diga o tempo medido na prosa. Medido
   aqui: 18,9 s.
3. **Fatia contra `minibatches`.** Decidido pela fatia (§2, decisão 1). O custo
   medido da alternativa era +40% por ajuste, e o bootstrap paga 100 vezes.
4. **`random.seed(0)` dentro de `scratch_np/multiple_regression.py`.** É a única
   linha de `random` da stdlib do pacote. Existe porque
   `scratch/multiple_regression.py` roda, no nível do módulo, 200 bootstraps de
   mediana sem semente (linhas 90–104), com dois `assert`. Os `assert` são
   robustos — o desvio das medianas de `far_from_100` fica perto de 100, e o
   limiar é 90 —, mas "robusto" não é "reprodutível", e um import não
   determinístico é exatamente o tipo de coisa que este livro não deixa passar.
   O teste `test_capitulo_numpy_usa_default_rng` varre **chunks de `.qmd`**, não
   `scratch_np/`, então isto não dispara teste; a decisão está registrada no
   docstring do módulo e aqui. **Não** reexportamos nada daquele bootstrap.
5. **`inputs` é (203, 4), não (200, 3).** A anotação da spec e o motivo em
   `REEXPORTA_DADOS` estão errados; a **assinatura** do contrato não. Corrigir o
   motivo do teste (§5) e deixar a spec para o passe de coerência global.
6. **`assert`s do Grus que poderiam não fechar — todos conferidos.**
   - `error == -6` e `squared_error == 36`: exatos (inteiros pequenos), sem
     `np.isclose`.
   - `sqerror_gradient == [-12, -24, -36]`: exato; `np.array_equal`, não
     `allclose`.
   - os quatro `assert` de `beta` da 12.3: fecham com `default_rng(0)` [medido].
   - os dois `assert` do bootstrap de medianas: fecham com `default_rng(0)`
     [medido: 0,056 < 1 e 94,3 > 90]. A margem do segundo é confortável mas não
     enorme; ele está no módulo **e** no chunk, com a mesma semente, então ou
     passa nos dois ou falha nos dois — não há como o site divergir do pacote.
   - os quatro `assert` de `p_value`: entradas literais do Grus, independentes de
     sorteio.
7. **Erros padrão mudaram, e um deles muda uma frase de leitura.** O erro padrão

   três afirmações que o capítulo faz sobre ele continuam **todas** verdadeiras
   (incerteza maior que a estimativa; ordem de grandeza acima da de `amigos`;
   coeficiente indistinguível de zero), mas "quase metade das vezes" vira "cerca
   de 40% das vezes" e "p = 0,46" vira "p = 0,40". Se o implementador medir algo
   diferente destes valores com `default_rng(0)`, é porque a ordem de consumo do
   gerador ficou diferente da planejada — **confira a ordem dos chunks antes de
   reescrever a prosa**.
8. **Um gerador só na 12.7, dois na 12.5.** Na 12.7 o mesmo `rng` sorteia as
   reamostras e os chutes iniciais: é o que torna a página reprodutível com uma

9. **O que continua sendo laço, e por quê.** Ficam: o laço sobre `num_steps` e o

10. **Nenhuma subida de gradiente.** Todo `gradient_step` deste capítulo leva

11. **`np.linalg.solve` aparece uma vez, como conferência** (chunk

    preta e não é o método ensinado. É o que a spec permite (tabela "Pode e
    deve"); `lstsq` e `polyfit` continuam fora.
12. **Risco de contexto para o cap. 13:** ele importa `inputs`, `predict` e
    `least_squares_fit` daqui. Se algo no módulo for renomeado, o capítulo 13
    quebra. Nada neste plano renomeia.
