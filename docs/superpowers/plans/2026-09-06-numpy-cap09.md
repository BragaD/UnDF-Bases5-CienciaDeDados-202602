## 2. O módulo `scratch_np/k_nearest_neighbors.py`

Arquivo novo, **completo**, pronto para salvar. Ninguém além do capítulo 9
importa daqui. As três funções são **idênticas** aos chunks das seções 9.1 e
9.3 — "o módulo é o chunk salvo em arquivo". A única diferença deliberada é o
nome dos dados de teste (`_X`, `_y`, `_d` com sublinhado, para não poluir o

com `_dados`/`_treino`.

```python
"""k-Vizinhos Mais Próximos com numpy — o que o capítulo 9 ensina.

A seção 9.1 escreve `raw_majority_vote`, `majority_vote` e `knn_classify`
inline; a seção 9.2 importa `knn_classify` daqui; a seção 9.3 escreve
`random_distances`. O código é o mesmo dos chunks — o módulo é o chunk salvo
em arquivo. Nenhum outro capítulo importa deste módulo.
"""
import numpy as np


def raw_majority_vote(labels) -> str:
    valores, contagens = np.unique(labels, return_counts=True)
    return valores[np.argmax(contagens)]


assert raw_majority_vote(['a', 'b', 'c', 'b']) == 'b'


def majority_vote(labels) -> str:
    """Assume que os rótulos estão ordenados do mais próximo ao mais distante."""
    valores, contagens = np.unique(labels, return_counts=True)
    vencedores = valores[contagens == contagens.max()]

    if len(vencedores) == 1:
        return vencedores[0]                # vencedor único
    else:
        return majority_vote(labels[:-1])   # tenta de novo sem o mais distante


# Empate: olha os 4 primeiros, então 'b'
assert majority_vote(['a', 'b', 'c', 'b', 'a']) == 'b'


def knn_classify(k: int,
                 X_train: np.ndarray,
                 y_train: np.ndarray,
                 new_point: np.ndarray) -> str:
    # A distância do ponto novo a cada linha de X_train, de uma vez.
    dists = np.linalg.norm(X_train - new_point, axis=1)

    # Os índices que ordenam os pontos do mais próximo ao mais distante...
    ordem = np.argsort(dists)

    # ...e os rótulos dos k primeiros votam.
    return majority_vote(y_train[ordem[:k]])


# Dois pontos perto da origem, três longe dela.
_X = np.array([[0.0, 0.0], [0.0, 1.0], [3.0, 3.0], [3.0, 4.0], [4.0, 3.0]])
_y = np.array(['perto', 'perto', 'longe', 'longe', 'longe'])
assert knn_classify(3, _X, _y, np.array([0.5, 0.5])) == 'perto'
assert knn_classify(3, _X, _y, np.array([3.5, 3.5])) == 'longe'


def random_distances(dim: int, num_pairs: int,
                     rng: np.random.Generator) -> np.ndarray:
    """Distâncias de `num_pairs` pares sorteados no cubo unitário de dimensão `dim`."""
    return np.linalg.norm(rng.random((num_pairs, dim))
                          - rng.random((num_pairs, dim)), axis=1)


_d = random_distances(3, 1000, np.random.default_rng(0))
assert _d.shape == (1000,)
assert 0.0 < _d.min() and _d.max() < np.sqrt(3)
```

**Verificado no scratchpad:** o módulo importa limpo e os cinco `assert` passam.

Decisões do módulo, para o revisor não precisar deduzi-las:

- **`Counter` sai; `np.unique(labels, return_counts=True)` entra.** Motivo pedagógico, não estético: com `Counter.most_common(1)` o empate é invisível; com `np.unique` + `np.argmax` o `raw_majority_vote` mostra na cara que *o primeiro máximo vence e ninguém avisa* — e como `np.unique` devolve os valores **ordenados**, o desempate é alfabético, que é justamente a regra do `scikit-learn` citada no callout de fechamento da 9.1. A função está na coluna "pode e deve" da spec.
- **`LabeledPoint` sai.** A convenção de array é `X (n, d)` + `y (n,)`, e é ela que o capítulo 8 prometeu ao capítulo 9 (*"a matriz de medidas e o array de espécies, pelos mesmos índices"*, `content/cap08/03-overfitting-e-underfitting.qmd`). Um `NamedTuple` de ponto + rótulo obrigaria a desempacotar a matriz de volta em 150 objetos.
- **`random_point` sai.** Virou `rng.random((num_pairs, dim))` dentro de `random_distances`: uma matriz de pontos, não um ponto por chamada.
- **`labels` sem anotação de tipo** nas duas votações: a função aceita tanto o array `y_train[ordem[:k]]` quanto a lista `['a', 'b', 'c', 'b', 'a']` do `assert` do Grus, e `np.unique` e `labels[:-1]` funcionam nos dois. Anotar `np.ndarray` seria mentira; anotar `Union` seria ruído.
- **O retorno é `np.str_`**, subclasse de `str` — a anotação `-> str` é honesta, `== 'b'` funciona, e a f-string formata normal.

def random_distances(dim: int, num_pairs: int,

## 4. Riscos e decisões

1. **A semente 12 fica — e é sorte medida, não fé.** Com `np.random.default_rng(12)`
   e `train_test_split`, a acurácia é 0,9778 (44/45) e a única célula fora da
   diagonal é uma *versicolor* prevista como *virginica* — **exatamente** a
   história que a prosa de hoje conta. Testadas também as sementes 0 (0,9556,
   dois erros cruzados), 1 (0,9556), 2 (0,9333), 3 (0,9778) e 42 (**1,0000**, que
   não ilustraria nada). Nenhuma troca é necessária; se por qualquer motivo a
   saída do implementador divergir da medida, **a frase se recalcula a partir da
   saída real**, nunca o contrário.
2. **`assert len(X_train) == 0.7 * 150` continua valendo** porque `split_data`
   corta em `int(len(data) * prob)` e 150 × 0,7 é exato. Não afrouxar.
3. **Igualdade de float:** não há nenhuma neste capítulo. `pct_correct` é saída
   de célula, não `assert`.
4. **O laço sobre as 45 flores de teste fica** (justificado no chunk
   `classifica-iris`), e o **laço sobre as 100 dimensões fica** (cada dimensão é
   um experimento). O que sumiu foi o laço sobre *pares de pontos* e sobre
   *pontos de treino*, que é o que a spec manda vetorizar.
5. **`np.char.replace`** é a limpeza do prefixo `Iris-`. Verificado em
   numpy 2.5.2 (a versão travada no `uv.lock`): funciona, devolve `dtype='<U10'`
   e **não emite aviso de depreciação**. Se um dia emitir, a alternativa é
   `np.array([s.split("-")[-1] for s in rotulos])`, que é o que o Grus faz linha
   a linha.
6. **`np.add.at` em vez de `+=`** na matriz de confusão: `+=` com arrays de
   índices perde as repetições em silêncio (medido: 1 no lugar de 2 num teste
   com pares repetidos). O `.exemplo` novo explica — é a classe de erro que este
   livro faz questão de mostrar.
7. **Duas leituras do mesmo arquivo** em `carrega-iris` (uma `float`, uma `str`).
   É deliberado e explicado na prosa: um array tem um tipo só. Alternativas
   (array estruturado, `genfromtxt(dtype=None)`) custam mais explicação do que
   economizam.
8. **Tempo de execução do capítulo:** desprezível. As 45 classificações levam
   ~0,6 ms; a maldição da dimensionalidade, ~0,5 s; o resto é leitura de arquivo
   e desenho. O capítulo era o mais lento em listas e deixa de ser — mas o texto
   **não** vende velocidade: as duas únicas afirmações de tempo ("menos de um
   segundo", "menos de um centésimo de segundo") são conservadoras e medidas.
