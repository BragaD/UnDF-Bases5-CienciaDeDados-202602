Mais de Duas Classes

Autor

Douglas Braga

Nota

Esta seção corresponde às seções 9.4, 9.6.4 e 9.6.5 de James et al. (2023).

Um hiperplano divide o espaço em dois lados, e o classificador de vetores de suporte dá uma classe a cada lado. Uma amostra de tecido de um tumor infantil, porém, pode vir de quatro tipos diferentes, e dois lados não bastam. Como juntar vários classificadores de duas classes numa resposta só? E o que fazer quando eles discordam?

A função numero_br escreve os números com a pontuação brasileira:

def numero_br(valor, casas=2):
    texto = f"{valor:,.{casas}f}"
    texto = texto.replace(",", "_").replace(".", ",").replace("_", ".")
    return texto.replace("-", "−")

Um contra um

A primeira resposta põe as classes para disputar duas a duas.

Com \(K\) classes, há \(\binom{K}{2} = K(K-1)/2\) pares de classes. A abordagem um contra um (one versus one) ajusta um classificador de duas classes para cada par, só com as observações daquelas duas classes. Um ponto novo passa pelos \(\binom{K}{2}\) classificadores, cada um dá o seu voto a uma das duas classes do seu par, e a previsão é a classe com mais votos.

Com 3 classes, são 3 classificadores; com 4, são 6.

Os dados são três nuvens de pontos no plano, nos vértices de um triângulo: a classe 0 embaixo à esquerda, a classe 1 embaixo à direita e a classe 2 em cima, misturadas no meio, onde as três se encontram. Os pontos de treino são 50 de cada classe, sorteados de normais com desvio padrão 1 nas duas coordenadas, em torno de três centros: \((0; 0)\) para a classe 0, \((3; 0)\) para a classe 1 e \((1{,}5; 2{,}6)\) para a classe 2. Depois deles, o mesmo gerador sorteia 3.000 pontos de teste por classe:

import numpy as np
import pandas as pd

rng = np.random.default_rng(16)
centros = np.array([[0, 0], [3, 0], [1.5, 2.6]])

def tres(n):
    classe = np.repeat([0, 1, 2], n)
    ruido = rng.normal(size=(3 * n, 2))
    pts = centros[classe] + ruido
    return pts, classe

X, y = tres(50)
X_teste, y_teste = tres(3_000)
pd.DataFrame(
    {"treino": np.bincount(y), "teste": np.bincount(y_teste)},
    index=pd.Index([0, 1, 2], name="classe"),
).style.format(thousands=".")
  treino teste
classe    
0 50 3.000
1 50 3.000
2 50 3.000
  • centros[classe] — uma linha de centros para cada elemento de classe: o centro da classe de cada ponto, somado ao ruído na linha seguinte.
  • np.bincount(y) — quantas vezes aparece cada inteiro de 0 até o maior valor de y: aqui, quantos pontos há em cada classe.
  • pd.DataFrame({...}, index=pd.Index([0, 1, 2], name="classe")) — a tabela com uma linha por classe; pd.Index dá nome à coluna dos rótulos. .style.format(thousands=".") — o ponto como separador de milhar.

Os pares, na ordem em que o SVC guarda os classificadores:

from itertools import combinations

pares = list(combinations(range(3), 2))
for k, (a, b) in enumerate(pares):
    print(f"coluna {k}: classe {a} contra classe {b}")
coluna 0: classe 0 contra classe 1
coluna 1: classe 0 contra classe 2
coluna 2: classe 1 contra classe 2
  • combinations(range(3), 2), do módulo itertools — todos os pares de elementos de range(3), sem repetir e sem importar a ordem; list os reúne numa lista. enumerate(pares) — percorre a lista junto com a posição k de cada par, e (a, b) separa as duas classes do par.

O SVC já ajusta um classificador por par quando y tem mais de duas classes. Com decision_function_shape="ovo" (o nome vem de one versus one), o decision_function devolve uma coluna por par, na ordem de pares, e o sinal de cada coluna diz qual classe do par leva o voto:

from sklearn.svm import SVC

ovo = SVC(kernel="linear", C=1, decision_function_shape="ovo")
ovo.fit(X, y)
d = ovo.decision_function(X_teste)
print("linhas de d, uma por ponto de teste:", numero_br(d.shape[0], 0))
print("colunas de d, uma por par:", d.shape[1])
nomes_pares = [f"par ({a}, {b})" for a, b in pares]
pd.DataFrame(d[:3], columns=nomes_pares, index=["ponto 0", "ponto 1", "ponto 2"]).style.format(numero_br)
linhas de d, uma por ponto de teste: 9.000
colunas de d, uma por par: 3
  par (0, 1) par (0, 2) par (1, 2)
ponto 0 6,26 4,66 0,14
ponto 1 3,92 2,57 −0,27
ponto 2 3,83 7,93 5,56
  • SVC(..., decision_function_shape="ovo") — o decision_function devolve uma coluna por par de classes. O padrão, "ovr", devolve uma coluna por classe; o ajuste é o mesmo nos dois casos.
  • [f"par ({a}, {b})" for a, b in pares] — uma lista com um nome por par, na ordem de pares, para rotular as colunas da tabela.

Cada linha da tabela é um ponto de teste, e cada coluna, o \(f(x)\) do classificador de um par.

As regiões de cada classe e as retas dos três classificadores de pares:

import matplotlib.pyplot as plt

Cada reta separa as duas classes do seu par, mas só vale como fronteira onde essas duas classes disputam o ponto. A reta do par \((0, 1)\), por exemplo, sobe entre a nuvem azul e a laranja; acima do centro, ela atravessa a região verde, onde a classe 2 já ganhou os seus dois pares e a disputa entre 0 e 1 não muda a previsão.

AvisoO sinal no um contra um

Com duas classes, \(f(x)\) positivo quer dizer classes_[1]. Nas colunas do "ovo", é o contrário: o valor positivo dá o voto à primeira classe do par.

O \(f(x)\) do classificador do par \((0, 1)\), ajustado à parte só com as classes 0 e 1, ao lado da primeira coluna:

par = y < 2
so_01 = SVC(kernel="linear", C=1)

Nos três pontos, os dois números têm o mesmo tamanho e sinais opostos. Os votos de um ponto, o primeiro de teste, par a par: o voto vai para \(a\) onde a coluna do par \((a, b)\) é positiva, e para \(b\) onde não é.

votos_0 = np.zeros(3, dtype=int)
for k, (a, b) in enumerate(pares):
    if d[0, k] > 0:
        vencedor = a

O ponto 0 é da classe 0, que ganha os seus dois pares; o terceiro voto, do par \((1, 2)\), vai para a classe 1. A função vota faz a mesma conta para todos os pontos de uma vez, uma coluna de d por vez:

def vota(d, K):
    votos = np.zeros((len(d), K), dtype=int)
    for k, (a, b) in enumerate(combinations(range(K), 2)):
        a_ganha = d[:, k] > 0
        votos[a_ganha, a] += 1
        votos[~a_ganha, b] += 1
    return votos

votos = vota(d, 3)
  • np.zeros((n, K), dtype=int) — uma matriz de n linhas e K colunas, cheia de zeros inteiros: uma linha por ponto, uma coluna por classe. Com um número só, np.zeros(3, dtype=int), é uma fila de três zeros.
  • votos[a_ganha, a] += 1 — nas linhas em que a_ganha é True, soma 1 na coluna da classe a. O ~ troca True por False e vice-versa: ~a_ganha marca as linhas em que o voto vai para b.

Cada linha de votos tem os votos das classes 0, 1 e 2. Os votos do ponto de teste mais perto de cada centro, e do mais perto do meio do triângulo, a média dos três centros:

meio = centros.mean(axis=0)
alvos = np.vstack([centros, meio])
linhas = []
for nome, c in zip(["centro 0", "centro 1", "centro 2", "meio"], alvos):
    dist = np.linalg.norm(X_teste - c, axis=1)
    i = dist.argmin()
    linhas.append({
        "mais perto de": nome,
        "classe": y_teste[i],
        "votos 0": votos[i, 0],
        "votos 1": votos[i, 1],
        "votos 2": votos[i, 2],
    })
pd.DataFrame(linhas).style.hide()
mais perto de classe votos 0 votos 1 votos 2
centro 0 0 2 1 0
centro 1 1 1 2 0
centro 2 2 1 0 2
meio 2 2 1 0

Com axis=1, a norma é calculada linha a linha, e argmin dá a posição do menor valor, o ponto mais perto.

Perto de cada centro, a classe do centro ganha os seus dois pares, e o terceiro classificador, que não a envolve, dá o terceiro voto a uma das outras duas classes. O ponto do meio é da classe 2, mas a classe 0 ganha os dois pares de que participa: perto de onde as nuvens se encontram, os classificadores podem levar o voto para uma classe que não é a do ponto.

Com 3 classes, os 3 votos de um ponto se dividem em 2, 1 e 0, ou num empate de 1 a 1 a 1. A classe mais votada é sempre a previsão do SVC? A tabela cruza as duas, ponto a ponto:

prev = ovo.predict(X_teste)
mais = votos.argmax(axis=1)

e_ovo = (prev != y_teste).mean()

pd.crosstab(mais, prev, rownames=["mais votada"], colnames=["predict"])

0 3161 0 0

2 0 0 2843
  • votos.argmax(axis=1) — em cada linha, a posição da maior contagem: a classe mais votada. votos.max(axis=1) — a maior contagem de cada linha.
  • pd.crosstab(a, b, rownames, colnames) — conta quantos pontos há em cada combinação de um valor de a, nas linhas, com um valor de b, nas colunas; rownames e colnames dão o nome das linhas e das colunas.

Nos 9.000 pontos de teste, a tabela só tem contagens na diagonal: a classe mais votada é a previsão do SVC, e nenhum ponto tem empate. A taxa de erro de teste é 0,1141. Um empate só acontece onde cada classe ganha um par, numa região pequena perto de onde as três retas quase se encontram, e nenhum ponto de teste caiu nela. O SVC aceita break_ties=True, que só funciona com o padrão "ovr" e desempata pela coluna de maior valor do decision_function.

Um contra todos

A outra resposta põe cada classe contra todas as outras juntas.

A abordagem um contra todos (one versus all, também chamada de um contra o resto) ajusta \(K\) classificadores. O \(k\)-ésimo trata a classe \(k\) como \(+1\) e todas as outras juntas como \(-1\), e dá a cada ponto \(x^*\) um escore

\[ f_k(x^*) = \beta_{0k} + \sum_{j=1}^{p} \beta_{jk} x^*_j. \]

A previsão é a classe de maior escore.

Com \(f_k(x^*)\) positivo, \(x^*\) fica do lado da classe \(k\) na fronteira do \(k\)-ésimo classificador; com negativo, do lado das outras. Quanto maior o \(f_k(x^*)\), mais esse classificador aposta na classe \(k\).

O OneVsRestClassifier monta os \(K\) classificadores a partir de um SVC de duas classes. Os três escores do primeiro ponto de teste, e a tabela que cruza, nos 9.000, a classe de maior escore com o predict:

from sklearn.multiclass import OneVsRestClassifier

ovr = OneVsRestClassifier(SVC(kernel="linear", C=1))
ovr.fit(X, y)
print("classificadores:", len(ovr.estimators_))
F = ovr.decision_function(X_teste)
for k in range(3):
    print(f"f_{k} do ponto 0:", numero_br(F[0, k]))
print("predict do ponto 0:", ovr.predict(X_teste[:1])[0])
p_ovr = ovr.predict(X_teste)
maior = F.argmax(axis=1)
pd.crosstab(maior, p_ovr, rownames=["maior escore"], colnames=["predict"])
classificadores: 3
f_0 do ponto 0: 3,98
f_1 do ponto 0: −5,52
f_2 do ponto 0: −3,54
predict do ponto 0: 0
predict 0 1 2
maior escore
0 2998 0 0
1 0 2999 0
2 0 0 3003
  • OneVsRestClassifier(estimador), de sklearn.multiclass — ajusta uma cópia do estimador para cada classe, com essa classe contra todas as outras. ovr.estimators_ — a lista dos classificadores ajustados, um por classe.
  • ovr.decision_function(X) — o escore \(f_k\) de cada classificador, uma coluna por classe; o predict dá a classe da coluna de maior escore. F.argmax(axis=1) — em cada linha, a posição do maior escore.

O ponto 0 tem um só escore positivo, o da classe 0, e é ela que o predict dá. Nos 9.000 pontos, a tabela só tem contagens na diagonal: a classe de maior escore é sempre a previsão. Quantos pontos de teste têm, como o ponto 0, exatamente um \(f_k\) positivo? A tabela conta os pontos pelo número de escores positivos:

positivos = (F > 0).sum(axis=1)
contagem = pd.DataFrame({"pontos": np.bincount(positivos, minlength=4)},

  • np.bincount(positivos, minlength=4) — a contagem de cada valor, com ao menos 4 posições, para que o valor sem nenhum ponto apareça com zero.

Dos 9.000 pontos de teste, 7.550 têm um só \(f_k\) positivo. Nos outros, a regra pelo sinal não decide: 855 não têm nenhum escore positivo, e nenhum classificador reclama o ponto para a sua classe; 595 têm dois, e dois classificadores reclamam o mesmo ponto. Nenhum tem os três escores positivos. O maior escore resolve os dois casos.

Antes de ver a figura: em que parte do plano devem ficar os pontos sem nenhum escore positivo? E os pontos com mais de um?

A zona cinza fica no meio, onde as três nuvens se encontram: ali, os três classificadores põem o ponto do lado de “todas as outras classes”, e nenhum escore é positivo. As faixas hachuradas saem dos vértices da zona cinza para as bordas, cada uma entre duas nuvens: ali, mais de um classificador põe o ponto do lado da sua classe. O que o SVC guarda

Com o padrão, decision_function_shape="ovr", o decision_function do SVC devolve uma coluna por classe. Seria esse o um contra todos? Não: o SVC ajusta sempre um classificador por par, e o "ovr" monta cada coluna a partir dos votos do um contra um, sem ajustar nenhum classificador um contra todos.

Quando \(p\) é muito maior que \(n\)

Com 2.308 colunas e 63 amostras, que papel sobra para o C? Ele é o preço da folga, e só pesa quando algum ponto de treino paga folga, isto é, fica dentro da margem ou do lado errado dela num par. Para cada C da grade, os erros de treino e de teste e os pontos de treino com \(y_i f(x_i) < 1 - 0{,}001\) em algum par, os que violam a margem além da tolerância do ajuste. Em cada par, \(y_i = 1\) para a primeira classe e \(-1\) para a segunda, como no sinal das colunas do "ovo":

y_np = y_tr.to_numpy()
grade = [0.0001, 0.001, 0.01, 0.1, 1, 10, 100]
linhas = []
for c in grade:
    m = SVC(kernel="linear", C=c, decision_function_shape="ovo")
    m.fit(X_tr, y_tr)
    d_c = m.decision_function(X_tr)
    viola = np.zeros(len(y_np), dtype=bool)
    for k, (a, b) in enumerate(combinations(m.classes_, 2)):
        yf = np.where(y_np == a, d_c[:, k], -d_c[:, k])
        do_par = (y_np == a) | (y_np == b)
        viola |= do_par & (yf < 1 - 1e-3)
    linhas.append({
        "C": c,
        "erros de treino": (m.predict(X_tr) != y_tr).sum(),
        "erros de teste": (m.predict(X_te) != y_te).sum(),
        "pontos com y·f < 1 − 0,001": viola.sum(),
    })

De 0,01 a 100, o C não muda nada: nenhum ponto de treino viola a margem de nenhum par, e os erros são os mesmos. Só os C muito pequenos mexem no ajuste. Votos ou escores

E o um contra todos, nos tumores? O LinearSVC da seção 16.2 usa essa abordagem por padrão, e o OneVsRestClassifier a monta com o SVC:

Lado a lado, as duas abordagens:

um contra um um contra todos
ajustes \(K(K-1)/2\) \(K\)
dados de cada um as duas classes do par todas as observações
decide por mais votos maior escore
empate votos iguais (fica a primeira classe) zero ou vários escores positivos (decide o maior)

Com 4 tumores, são 6 classificadores contra 4, e a distância cresce depressa: o número de pares cresce com o quadrado de \(K\), e o de classificadores um contra todos, só com \(K\). Como cada classificador de par vê só as observações de duas classes, o um contra um compensa quando ajustar com todas as observações de uma vez é caro; com muitas classes, os pares se multiplicam, e os \(K\) ajustes do um contra todos podem sair mais baratos.
