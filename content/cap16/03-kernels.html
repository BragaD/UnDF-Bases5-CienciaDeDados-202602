Kernels

Autor

Douglas Braga

Nota

Esta seção corresponde às seções 9.3, 9.6.2 e 9.6.3 de James et al. (2023).

Uma classe se concentra no meio do plano; a outra fica em duas nuvens, uma de cada lado. Uma reta só divide o plano em dois lados, e a classe do meio está entre as duas nuvens da outra. Dá para manter a margem, as folgas e os vetores de suporte e, mesmo assim, ganhar uma fronteira curva?

Quando a fronteira não é reta

Os pontos são sorteados de normais com desvio padrão 1 nas duas coordenadas. A primeira metade das linhas é deslocada para perto de \((2; 2)\), e o quarto seguinte, para perto de \((-2; -2)\): esses três quartos formam a classe \(-1\). O último quarto fica em torno da origem e forma a classe \(1\). São 200 pontos de treino e, sorteados depois deles, 10.000 de teste. Em X[: n // 2] += 2, o : n // 2 pega as linhas da primeira até a de posição n // 2 - 1, e as duas colunas delas recebem 2 a mais:

import numpy as np

rng = np.random.default_rng(16)

def nuvens(n):
    X = rng.normal(size=(n, 2))
    X[: n // 2] += 2
    X[n // 2 : 3 * n // 4] -= 2
    i = np.arange(n)
    y = np.where(i < 3 * n // 4, -1, 1)
    return X, y

X, y = nuvens(200)
X_teste, y_teste = nuvens(10_000)
print("classe −1:", (y == -1).sum())
print("classe 1:", (y == 1).sum())
classe −1: 150
classe 1: 50

A função numero_br escreve os números com a pontuação brasileira:

def numero_br(valor, casas=2):
    texto = f"{valor:,.{casas}f}"
    texto = texto.replace(",", "_").replace(".", ",").replace("_", ".")
    return texto.replace("-", "−")

O primeiro candidato é o classificador de vetores de suporte da seção 16.2, com C=1:

from sklearn.svm import SVC

linear = SVC(kernel="linear", C=1)
linear.fit(X, y)
prev = linear.predict(X_teste)
print("previsões da classe −1:", numero_br((prev == -1).sum(), 0))
print("previsões da classe 1:", numero_br((prev == 1).sum(), 0))
print("erro de teste:", numero_br((prev != y_teste).mean(), 4))
print("maior |coef_|, com três casas:", numero_br(np.abs(linear.coef_).max(), 3))
print("intercept_:", numero_br(linear.intercept_[0]))
previsões da classe −1: 10.000
previsões da classe 1: 0
erro de teste: 0,2500
maior |coef_|, com três casas: 0,000
intercept_: −1,00

Os 10.000 pontos de teste recebem a classe \(-1\), e o erro de teste, 0,25, é a fração da classe \(1\), um quarto dos pontos por construção. Os coeficientes saem zero até a terceira casa, e o intercepto, \(-1{,}00\): \(f(x)\) fica perto de \(-1\) no plano inteiro. Os dados e as regiões desse classificador:

import matplotlib.pyplot as plt

malha = np.column_stack([g1.ravel(), g2.ravel()])

def classes(ax, pts, y):

  • ax.get_legend_handles_labels() — os marcadores e os rótulos que um gráfico poria na legenda; passados a fig.legend, aparecem uma vez só para a figura toda.

No painel da direita, a cor do fundo é a classe que o classificador daria a cada ponto do plano. Não há fronteira a traçar: \(f\) não muda de sinal. Uma reta que separe a nuvem do meio de uma das nuvens de fora deixa a outra nuvem de fora do mesmo lado que a do meio, e o ajuste prefere não separar nada.

Nas figuras seguintes, a leitura é a mesma, e as curvas cinza marcam a fronteira \(f(x) = 0\), contínua, e as bordas da margem, \(f(x) = \pm 1\), tracejadas.

Na regressão, uma relação curva entre preditor e resposta se ajusta com termos como \(X^2\) e \(X^3\) (seção 8.5). O classificador de vetores de suporte aceita a mesma ideia: em vez de \(X_1\) e \(X_2\), ele recebe também \(X_1^2\), \(X_1 X_2\) e \(X_2^2\) e procura um hiperplano nesse espaço de 5 colunas. Nele, a fronteira é plana; no plano original, \(f(x) = 0\) vira uma equação do segundo grau em \(X_1\) e \(X_2\), e a curva que ela descreve pode separar a nuvem do meio das outras duas. As 5 colunas de um ponto, o ponto 0:

import pandas as pd
from sklearn.preprocessing import PolynomialFeatures

colunas = PolynomialFeatures(2, include_bias=False)
X5 = colunas.fit_transform(X)
print(f"ponto 0: X1 = {numero_br(X[0, 0])}, X2 = {numero_br(X[0, 1])}")
print("colunas de X:", X.shape[1], "· colunas de X5:", X5.shape[1])
nomes5 = colunas.get_feature_names_out(["X1", "X2"])
pd.DataFrame(X5[:1], columns=nomes5, index=["ponto 0"]).style.format(numero_br)
ponto 0: X1 = 1,41, X2 = 2,63
colunas de X: 2 · colunas de X5: 5
  X1 X2 X1^2 X1 X2 X2^2
ponto 0 1,41 2,63 1,97 3,70 6,92
  • PolynomialFeatures(2, include_bias=False), de sklearn.preprocessing — acrescenta às colunas os termos até o grau 2, o primeiro argumento: os quadrados e os produtos dois a dois. include_bias=False não cria a coluna de uns, porque o intercepto já é do SVC. .fit_transform(X) — aprende quantas colunas há e devolve a tabela ampliada.
  • .get_feature_names_out(["X1", "X2"]) — os nomes das colunas que o passo produz, a partir dos nomes dados às colunas de entrada.
  • pd.DataFrame(X5[:1], columns=nomes5, index=[...]), do pandas — a primeira linha de X5 numa tabela, com as colunas e a linha rotuladas; .style.format(numero_br) escreve cada valor com a numero_br.

As duas primeiras colunas repetem \(X_1\) e \(X_2\); as outras três são os quadrados e o produto, e dá para conferir cada uma com os dois números do ponto. O Pipeline faz essa transformação antes do SVC, no fit e no predict:

from sklearn.pipeline import make_pipeline

ampliado = make_pipeline(
    PolynomialFeatures(2, include_bias=False), SVC(kernel="linear", C=1)
)
ampliado.fit(X, y)
p_amp = ampliado.predict(X_teste)
e_amp = (p_amp != y_teste).mean()
print("erro de teste:", numero_br(e_amp, 4))
erro de teste: 0,1035
  • make_pipeline(passo1, passo2), de sklearn.pipeline — encadeia os passos: o fit e o predict passam os dados pelo primeiro e entregam o resultado ao segundo.

Com as 5 colunas, o erro de teste cai de 0,25 para 0,1035. A fronteira, desenhada no plano original:

fig, ax = plt.subplots(figsize=(3.8, 4.2), layout="constrained")
regioes(ax, ampliado)
classes(ax, X, y)
ax.set_ylabel("$X_2$")
fig.legend(handles, rotulos, ncols=2, loc="outside lower center")
plt.show()

No espaço de 5 colunas, a fronteira é um hiperplano; no plano original, são duas curvas, e a faixa laranja entre elas contém a nuvem do meio e deixa as duas nuvens azuis de fora, uma de cada lado. Só que o número de colunas cresce depressa: com \(p\) preditores, o grau 2 já dá \(p\) quadrados e \(p(p-1)/2\) produtos, e os graus maiores crescem mais depressa.

Produtos internos e kernels

Como chegar a uma fronteira como essa sem montar as colunas? A resposta passa pelo produto interno de duas observações, o produto escalar da seção 4.1: a soma dos produtos coordenada a coordenada. Para os pontos \(a = (1; 2)\) e \(b = (3; -1)\):

a = np.array([1, 2])
b = np.array([3, -1])
print("<a, b> =", a @ b)
<a, b> = 1

A conta é \(1 \cdot 3 + 2 \cdot (-1) = 1\). Com \(p\) coordenadas,

\[ \langle x_i, x_{i'} \rangle = \sum_{j=1}^{p} x_{ij}\, x_{i'j}. \]

A solução do classificador de vetores de suporte pode ser escrita só com produtos internos. Com \(S\) o conjunto dos vetores de suporte,

\[ f(x) = \beta_0 + \sum_{i \in S} \alpha_i \langle x, x_i \rangle, \]

com um número \(\alpha_i\) para cada vetor de suporte; para os outros pontos de treino, \(\alpha_i = 0\). No SVC, os \(\alpha_i\) estão em dual_coef_, com o sinal da classe de cada vetor de suporte já embutido, e \(\beta_0\) está em intercept_.

No ajuste e na previsão, os pontos só aparecem dentro de produtos internos: no ajuste, entre os pares de pontos de treino; na previsão, entre o ponto novo \(x\) e cada vetor de suporte. A ideia é trocar o produto interno por outra função de duas observações, \(K(x_i, x_{i'})\), chamada kernel (núcleo), que mede quanto as duas se parecem. O produto interno é o kernel linear, e com ele se volta ao classificador de vetores de suporte.

Com outro kernel na mesma soma, sai um classificador novo:

Com um kernel \(K\), a máquina de vetores de suporte (SVM, de support vector machine) usa

\[ f(x) = \beta_0 + \sum_{i \in S} \alpha_i\, K(x, x_i). \]

O kernel polinomial de grau \(d\) é

\[ \begin{aligned} &K(x_i, x_{i'}) = \\ &\Big(1 + \sum_{j=1}^{p} x_{ij}\, x_{i'j}\Big)^{d}, \end{aligned} \]

e o kernel radial, com \(\gamma > 0\), é

\[ \begin{aligned} &K(x_i, x_{i'}) = \\ &\exp\Big(-\gamma \sum_{j=1}^{p} (x_{ij} - x_{i'j})^2\Big). \end{aligned} \]

No radial, a soma do expoente é o quadrado da distância euclidiana entre os dois pontos. O kernel vale 1 para um ponto consigo mesmo e cai para perto de zero quando os dois se afastam: ele mede a semelhança pela distância.

O que o kernel polinomial calcula? Com \(d = 2\) e duas coordenadas, abrir o quadrado de \(1 + x_1 x'_1 + x_2 x'_2\) dá seis termos, e cada um é o produto de uma coluna calculada em \(x\) pela mesma coluna calculada em \(x'\). As colunas são \(1\), \(\sqrt{2}\,x_1\), \(\sqrt{2}\,x_2\), \(x_1^2\), \(\sqrt{2}\,x_1 x_2\) e \(x_2^2\), e a função phi as monta. O kernel e o produto interno nessas colunas, primeiro para \(a\) e \(b\), depois para todos os pares dos 200 pontos de treino:

def phi(A):
    x1 = A[:, 0]
    x2 = A[:, 1]
    r = np.sqrt(2)
    return np.column_stack([np.ones(len(A)), r * x1, r * x2, x1**2, r * x1 * x2, x2**2])

print("(1 + <a, b>)² =", (1 + a @ b) ** 2)
fa, fb = phi(np.vstack([a, b]))
print("<φ(a), φ(b)> =", numero_br(fa @ fb, 4))
K2 = (1 + X @ X.T) ** 2
F = phi(X)
dif = np.abs(K2 - F @ F.T).max()
print("pares de pontos de treino:", numero_br(K2.size, 0))
print("maior diferença entre os dois, abaixo de um milionésimo:", dif < 1e-6)
(1 + <a, b>)² = 4
<φ(a), φ(b)> = 4,0000
pares de pontos de treino: 40.000
maior diferença entre os dois, abaixo de um milionésimo: True
  • np.ones(k) — um array com k uns: a coluna constante. np.sqrt(2) — a raiz quadrada, \(\sqrt{2}\).
  • fa, fb = phi(...) — phi devolve duas linhas, uma por ponto, e cada uma vai para um nome.
  • X.T — a transposta: as linhas viram colunas. X @ X.T é a matriz dos produtos internos entre cada par de linhas de X, 200 por 200; K2.size é o número de elementos dela.

Para \(a\) e \(b\), as duas contas dão 4. Nos 40.000 pares dos pontos de treino, a diferença entre elas fica abaixo de um milionésimo, o que sobra do arredondamento: o kernel polinomial de grau 2 dá o mesmo número que o produto interno nessas seis colunas, sem calculá-las. Usar esse kernel equivale a ajustar o classificador de vetores de suporte num espaço com os termos de grau até 2, cada um multiplicado por uma constante fixa, \(\sqrt{2}\) ou 1; com grau \(d\), os termos vão até o grau \(d\).

As colunas do PolynomialFeatures são as mesmas sem essas constantes e sem a coluna de uns. Por isso o kernel dá uma fronteira do mesmo tipo que a da figura acima, mas não a mesma. Os erros de teste dos dois:

poli2 = SVC(kernel="poly", degree=2, gamma=1, coef0=1, C=1)
poli2.fit(X, y)
p_k2 = poli2.predict(X_teste)
pd.DataFrame({
    "ajuste": ["5 colunas do PolynomialFeatures", "kernel polinomial de grau 2"],
    "erro de teste": [e_amp, (p_k2 != y_teste).mean()],
}).style.format({"erro de teste": "{:.4f}"}, decimal=",").hide()
ajuste erro de teste
5 colunas do PolynomialFeatures 0,1035
kernel polinomial de grau 2 0,1045
  • SVC(kernel="poly", degree=2, gamma=1, coef0=1) — a máquina de vetores de suporte com o kernel polinomial: o SVC multiplica o produto interno por gamma, soma coef0 e eleva a degree. Com gamma=1 e coef0=1, é a fórmula do kernel polinomial acima, com \(d\) igual a degree.

Os erros, 0,1035 e 0,1045, ficam próximos sem coincidir: as constantes \(\sqrt{2}\) põem as colunas em escalas diferentes das do PolynomialFeatures, e o mesmo C, que limita o tamanho dos coeficientes, pesa de um jeito diferente em cada uma.

Por que não montar as colunas, como no começo da seção? As colunas do espaço ampliado dependem de \(p\) e do grau; com o kernel, o ajuste precisa de \(K(x_i, x_{i'})\) para cada par de pontos de treino, e cada um custa os \(p\) produtos de \(\langle x_i, x_{i'} \rangle\), qualquer que seja o grau. Com \(p = 16\) preditores:

from math import comb

p = 16
for n in [200, 2_000, 20_000]:
    print(f"pares de pontos com n = {numero_br(n, 0)}:", numero_br(comb(n, 2), 0))
graus_d = [2, 3, 5, 10]
pd.DataFrame({
    "grau d": graus_d,
    "colunas do espaço ampliado": [comb(p + d, d) - 1 for d in graus_d],
}).style.format(thousands=".").hide()
pares de pontos com n = 200: 19.900
pares de pontos com n = 2.000: 1.999.000
pares de pontos com n = 20.000: 199.990.000
grau d colunas do espaço ampliado
2 152
3 968
5 20.348
10 5.311.734
  • comb(n, k), do módulo math — de quantas formas se escolhem k itens entre n, sem importar a ordem: comb(n, 2) é o número de pares. comb(p + d, d) - 1 conta os termos de grau 1 até \(d\) em \(p\) variáveis, sem o termo constante.

Na tabela, as colunas passam dos 16 produtos do kernel já no grau 2 e chegam a milhões no grau 10. O número de pares não depende do grau, mas cresce com o quadrado de \(n\). O kernel compensa quando o grau é alto e \(n\) não é enorme. O kernel radial é definido direto como função de dois pontos: não há colunas a montar.

Num ponto novo \(x\), os vetores de suporte distantes de \(x\) quase não entram na soma de \(f(x)\) com o kernel radial; é a vizinhança de \(x\) que decide a classe.

O SVC faz essas contas no fit e no predict; refazer a soma à mão serve só para ver a fórmula funcionando. O código ajusta um SVC com kernel radial e \(\gamma = 1\) e calcula o kernel entre 50 pontos de teste e os vetores de suporte, numa matriz K com uma linha por ponto e uma coluna por vetor de suporte:

from sklearn.metrics.pairwise import rbf_kernel

gama_r = 1
radial = SVC(kernel="rbf", gamma=gama_r, C=1)
radial.fit(X, y)
x_novos = X_teste[:50]
sv = radial.support_vectors_
K = rbf_kernel(x_novos, sv, gamma=gama_r)
print("linhas de K, uma por ponto:", K.shape[0])
print("colunas de K, uma por vetor de suporte:", K.shape[1])
d2 = ((x_novos[0] - sv[0]) ** 2).sum()
print("K[0, 0] do rbf_kernel:", numero_br(K[0, 0], 4))
print("exp(−γ·d²) à mão:", numero_br(np.exp(-gama_r * d2), 4))
linhas de K, uma por ponto: 50
colunas de K, uma por vetor de suporte: 86

Quanto dá para errar menos?

Os pontos foram simulados, e por isso o classificador de Bayes da seção 7.7, a regra de menor taxa de erro esperada, é conhecido. A classe \(1\) é um quarto dos pontos, com densidade normal centrada na origem; a classe \(-1\) é a mistura de metade dos pontos em torno de \((2; 2)\) e um quarto em torno de \((-2; -2)\). A regra de Bayes escolhe a classe com o maior produto de proporção e densidade. A constante das normais é a mesma nas três e se cancela:

def normal(pts, centro):
    d2 = ((pts - centro) ** 2).sum(axis=1)
    return np.exp(-d2 / 2)

meio = 0.25 * normal(X_teste, [0, 0])
lados = 0.5 * normal(X_teste, [2, 2]) + 0.25 * normal(X_teste, [-2, -2])
regra = np.where(meio > lados, 1, -1)
bayes = (regra != y_teste).mean()
print("regra de Bayes, erro de teste:", numero_br(bayes, 4))
print("SVC escolhido, erro de teste:", numero_br(erro_busca, 4))
regra de Bayes, erro de teste: 0,0942
SVC escolhido, erro de teste: 0,1054

Nos mesmos 10.000 pontos, a regra de Bayes erra 0,0942, e o SVC escolhido, 0,1054: a diferença, \(0{,}1054 - 0{,}0942 = 0{,}0112\), é o que o ajuste com 200 pontos de treino deixa de acertar em relação à regra que conhece as distribuições.

Os padrões do SVC

De onde veio o \(\gamma\) que o SVC usa quando não damos nenhum? Sem o argumento gamma, ele usa gamma="scale", que calcula no fit, com os dados de treino,

\[ \gamma = \frac{1}{p \cdot v}, \]

com \(p\) o número de colunas e \(v\) a variância de todos os números de X juntos:

p_x = X.shape[1]
gama = 1 / (p_x * X.var())
print("X.var():", numero_br(X.var(), 4))
print("1 / (p · X.var()):", numero_br(gama, 4))
padrao = SVC(kernel="rbf")
padrao.fit(X, y)
com_num = SVC(kernel="rbf", gamma=gama)
com_num.fit(X, y)

f_num = com_num.decision_function(X)
print("maior diferença nos 200, abaixo de um milionésimo:",
      np.abs(f_padrao - f_num).max() < 1e-6)
pd.DataFrame({"gamma='scale'": f_padrao[:3], "esse γ": f_num[:3]},
             index=["ponto 0", "ponto 1", "ponto 2"]).style.format(numero_br)

Com coef0=0 e grau 3, o kernel é \(K(x, x_i) = (\gamma \langle x, x_i \rangle)^3\), e \(f(x) - \beta_0\) só tem termos de grau 3: vale o oposto em \((-2; -2)\) do que vale em \((2; 2)\), onde ficam as duas nuvens da classe \(-1\). Um \(\beta_0\) que ponha as duas do lado \(-1\) leva junto a nuvem do meio, e o ajuste prevê \(-1\) para todos: nenhuma previsão da classe \(1\) na tabela, com erro de 0,25, como o linear.

Com coef0=1, o \(1 +\) da fórmula traz os termos de grau 0, 1 e 2, e o erro de teste cai para 0,1055. O radial com o \(\gamma\) de "scale" erra 0,1053.

Os modelos da comparação são esse classificador de vetores de suporte, a análise discriminante linear (LDA) da seção 9.7 e o kernel radial com três valores de \(\gamma\); os SVC, todos com C=1.   • m.decision_function(X_te) num Pipeline — passa as linhas pelo StandardScaler e entrega o resultado ao modelo.

A escala dos preditores

Sem o StandardScaler, o que muda? E se o colesterol estiver em mmol/L em vez de mg/dL, dividido por 38,67? A troca de unidade muda o resultado com a padronização? E sem ela? O kernel radial com o \(\gamma\) de "scale", nas quatro combinações, e os erros nos 90 pacientes de teste:

X_tr2 = X_tr.copy()
X_te2 = X_te.copy()
X_tr2["colesterol"] = X_tr2["colesterol"] / 38.67
X_te2["colesterol"] = X_te2["colesterol"] / 38.67
unidades = [("mg/dL", X_tr, X_te), ("mmol/L", X_tr2, X_te2)]
quatro = []
for escala in ["sem", "com"]:
    for unidade, Xa, Xb in unidades:
        if escala == "com":
            m = make_pipeline(StandardScaler(), SVC(kernel="rbf"))
        else:
            m = SVC(kernel="rbf")
        m.fit(Xa, y_tr)
        previsto = m.predict(Xb)
        escore = m.decision_function(Xb)
        quatro.append({
            "escala": escala,
            "unidade": unidade,
            "erros": (previsto != y_te).sum(),
            "auc": roc_auc_score(y_te, escore),
        })

Sem a padronização, o modelo erra 32 dos 90 pacientes, contra 16 com o StandardScaler. Por que tanto? O código procura a coluna de maior variância e o \(\gamma\) que o "scale" calcula sem padronizar:

variancias = X_tr.var(ddof=0)
print("maior variância:", variancias.idxmax())
v = X_tr.to_numpy().var()
gama_cru = 1 / (16 * v)
print("γ sem escala:", f"{gama_cru:.1e}".replace(".", ",").replace("-", "−"))
maior variância: colesterol
γ sem escala: 1,2e−05
  • X_tr.var(ddof=0) — a variância de cada coluna, com divisor igual ao número de linhas. X_tr.to_numpy().var() — a variância de todos os números juntos, a que o gamma="scale" usa.

Sem a padronização, a coluna de maior variância é o colesterol, e o \(\gamma\) de "scale", calculado com a variância de todos os números da tabela juntos, sai perto de \(10^{-5}\). Nas distâncias entre pacientes, as colunas de variância grande pesam mais que as indicadoras de 0 e 1.

Mudar só a unidade do colesterol muda o resultado sem padronização, para 30 erros. Com ela, nada muda: continuam 16 erros, e as duas áreas são iguais na tabela. A padronização põe cada coluna na mesma escala, qualquer que seja a unidade de origem.

Escolhas e limites do kernel

O problema do classificador de vetores de suporte continua o mesmo; o que muda é a medida de semelhança entre dois pontos. O classificador depende dos pontos só pelos produtos internos, e trocar o produto interno por um kernel faz a conta num espaço com mais colunas sem montá-lo; no kernel polinomial, são os termos de grau até \(d\), cada um multiplicado por uma constante. No plano original, o hiperplano desse espaço aparece como uma fronteira curva.

Em troca, há mais a escolher: o kernel, o \(\gamma\) ou o grau, e o C do SVC, todos por validação cruzada e com os preditores na mesma escala. No simulado, a escolha chegou a 0,1054 de erro de teste, contra 0,0942 da regra de Bayes; no Heart, o kernel radial mais flexível teve a menor área e o maior número de erros neste teste.

O método também tem limites. O ajuste precisa do kernel para cada par de pontos de treino, e esse número cresce com o quadrado de \(n\). O SVC devolve um escore \(f(x)\) e uma classe, não uma probabilidade. E, fora do kernel linear, não há um coeficiente por preditor para ler: a fronteira fica escrita como uma soma sobre os vetores de suporte.
